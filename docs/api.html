API reference

Four functions sharing one parse core. Import them from 'guessit-next' — or from ./src/index.js inside a checkout. Every field a function returns is part of the public contract: rename nothing without a migration.

categorize(name) → CategoryResult

Answers: what does this one torrent or release name represent? Use it before downloading to decide what a single name stands for. Each name lands in exactly one kind, first match wins: collection > season_batch > episode_collection > episode > movie > others.

categorize('Show Name S01E01-E13 1080p');
// → { kind: 'episode_collection', season: 1, episode: 1, episodeEnd: 13, … }

categorize('Show Name S01-S03 1080p');
// → { kind: 'collection', seasonRange: [1, 3], seasonList: [1, 2, 3], … }
FieldMeaning
kindone of collection | season_batch | episode | episode_collection | movie | others
seasonthe single season the item belongs to (or null)
episodethe (start) episode number (or null)
episodeEndlast episode of a range or collection (or null)
seasonEndseason of episodeEnd, only when a range crosses seasons (or null)
seasonRange[min, max] seasons spanned by a multi-season item (or null)
seasonListexplicit sorted list of every season contained (or null)
isCompletePacktrue for “Complete Series” / “All Seasons” / “… COMPLETE”

extractSE(name) → SE

Answers: what season/episode structure does this name carry? Same parse core as categorize, without the kind decision — ranges are preserved, never collapsed.

extractSE('Show Name S01E01-E13 1080p');
// → { season: 1, episode: 1, episodeEnd: 13,
//     seasonEnd: null, seasonRange: null, seasonList: null }
FieldMeaning
season / episodestart of the structure (or null)
episodeEnd / seasonEndrange end; seasonEnd only for cross-season ranges
seasonRange / seasonListfor season spans with no episodes involved

classifyFile(candidate, opts?) → ClassificationResult

Answers: where does this one file belong in a media library? It reads the file name and its folder names — the folder usually knows the show title even when the file doesn't. It never returns skip: what counts as skippable (low confidence, incomplete downloads, non-media files) is your application's decision.

classifyFile({
  name: '10-Conclusion.mkv',
  source_path: '/data/torrents/Neutral Show/10-Conclusion.mkv',
  source_root: '/data/torrents',
  container_path: '/data/torrents/Neutral Show',
  relative_path: '10-Conclusion.mkv',
  file_size: 1024,
});
// → { type: 'series', title: 'Neutral Show', episode_title: 'Conclusion',
//     season: null, episode: 10, confidence: 0.9, … }

What to pass in

FieldMeaning
namefile name, e.g. Show - S01E02.mkv
source_pathfull path of the file
source_rootscan root the file was found under
container_pathcontaining folder (torrent root), if any
relative_pathpath relative to the container, if any (carries Season 02/… subfolders)
file_sizesize in bytes, if known (needed for the sample-size heuristic)

opts = { seriesAliases?: Record<string,string> } maps a detected title to its canonical name.

What comes back

FieldMeaning
typeseries | movie | extra (never skip)
titleshow or movie title
episode_titleepisode title, when derivable (or null)
series_aliasalternative title, e.g. a foreign arc name (or null)
yearrelease year (or null)
season / episodenumbers; a range collapses to its start episode here
episodeEndrange end for multi-episode files (or null)
confidence0–1, how sure the classifier is
reasonshort human-readable reason
extra_typefor extra: sample | trailer | behind | deleted | interview | featurette | short | special | extra

How confidence is set

EvidenceTypeConfidenceReason
explicit episode markerseries0.9Matched episode/season pattern
season marker onlyseries0.8Matched season pattern
year, no season/episodemovie0.75Matched year without season/episode
standalone file, nothing elsemovie0.65Defaulted standalone file to movie
extra marker (sample, trailer, …)extra≥ 0.85Detected <type> extra/special marker
A small movie-size file with no sample marker stays movie with a “sample-size suspect” reason suffix — your app can flag it while the file stays editable. Only a real sample marker routes to extra/sample.

classifyFiles(candidates, opts?) → { results, groups }

Answers: what does this whole folder contain, and do its files agree? Use it for one torrent folder or one directory listing. You get one result per input file (same order), plus one summary group per folder: agreed title and type, seasons and episodes inside, file counts, and a consistent flag with conflicts when a file disagrees with its folder. Extras never break agreement. Empty input returns { results: [], groups: [] }.

classifyFiles([
  { name: 'Show Name - S01E01.mkv', container_path: '/data/torrents/Show Pack', … },
  { name: 'Show Name - S01E02.mkv', container_path: '/data/torrents/Show Pack', … },
]);
// → { results: [ …one result per file, in order… ],
//     groups: [{ key: '/data/torrents/Show Pack', title: 'Show Name',
//       type: 'series', seasons: [1], episodesBySeason: { 1: [1, 2] },
//       fileCount: 2, episodeFileCount: 2, extraFileCount: 0,
//       consistent: true, conflicts: [] }] }
FieldMeaning
keyfolder path (or lone file path for loose files, which each form their own group)
title / typemajority identity across the group's series/movie results
seasonssorted unique seasons contained
episodesBySeason{ "<season>": [sorted unique episodes] }
fileCount / episodeFileCount / extraFileCounttotal files / files with an episode number / files classified as extras
consistentfalse when a file disagrees with the folder majority
conflictshuman-readable description of each disagreement

A disagreeing file keeps its result but gets lowered confidence with a conflict reason, so your app can route it for review.
