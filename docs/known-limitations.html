Known limitations

The parser works from the name alone — no catalogue, no network lookup, no per-title knowledge. Some name shapes are genuinely ambiguous to a name-only parser. These cases are documented deliberately: what happens, why, and how to work around it.

A yearless “complete” film reads as a complete pack

Movie Title COMPLETE 1080p (no year) → complete pack. “Complete” marks two unrelated things — a full series run and a full movie disc — and the only local signal separating them is the year: a series run spanning years carries none, a film carries its own.

Workaround: include the year (Movie Title (2020) COMPLETE 1080p stays a movie).

A bare number with no marker is a guess

Show Name - 720 is simultaneously a plausible resolution (720p), an absolute episode (720), and a season/episode split (7x20). The parser picks one; it cannot be right for every release because the name itself doesn't say which was meant.

Workaround: add the missing token — the p (720p), or an explicit marker (E720, S07E20).

The folder majority wins

When a file disagrees with the folder around it, the folder's identity wins and the file is flagged with consistent: false plus a conflict note (see classifyFiles). A mistitled file inside a correctly-named folder will therefore not pull the folder off course — but a correctly-titled file inside a wrong folder gets flagged too.

Workaround: treat conflicts as a review queue in your app rather than as errors.

Unknown tokens fall through

The parser knows a fixed set of patterns: resolutions, codecs, markers, season/episode shapes. A brand-new release tag it has never seen either lands in the title or leaves the name as others. It has no catalogue to learn from, so genuinely novel tokens need a human to teach it.

Workaround: open an issue with the obfuscated name (same tokens, fake title) so the pattern set can grow.

Titles are cleaned, never corrected

Separators become spaces and casing is normalized, but the words are never rewritten: a typo, an abbreviation, or a missing apostrophe in the filename stays in the returned title. Fixing spelling needs a real title database, which the parser deliberately does not call.

Workaround: match the returned title against your own library or a metadata source downstream.

Multi-episode files route by their first episode

classifyFile collapses S01E01-E13 to episode 1 for routing (one file, one slot), keeping 13 in episodeEnd. If your app needs the file listed under every episode it contains, expand the range yourself from episode + episodeEnd.
